# Frozen scope: Reading and Knowledge

This document records decisions for later phases. It is not an implementation brief for the current V1.

## Reading

### Global Homepage

The Reading summary remains limited to:

- New Research Recommendations
- Today’s Plan
- Open →

Internal reading folders and detailed research records must not appear on the Global Homepage.

### Future directory

- Reading will be a focused browsing surface, not an AI chat interface.
- The first layer will present current recommendations and the day’s reading plan.
- Detailed reading records will open only after entering the Reading module.
- Keyword retrieval may search reading titles, topics, and stored notes.
- Temporary detail views must use overlays or fixed internal areas and must not reflow the whole page.
- Real records will later be read from user-authorized local files; V1 examples must remain clearly marked as examples.

The internal Reading folder taxonomy and final card template are not yet frozen and must not be invented during V1.

## Knowledge

### Global Homepage

- Knowledge remains a separate header entry.
- Knowledge content must not be mixed into the Application or Reading summaries.

### Future directory

- Knowledge will act as a central browser for the user’s existing local archive, including an Obsidian vault and other authorized folders.
- The dashboard will retrieve and display existing files rather than create a second knowledge database.
- Folder access must be explicitly selected or authorized by the user; the browser must not silently scan the computer.
- Private files must remain local and must not be committed to the public GitHub repository.
- Search remains keyword retrieval. It is not an AI chat interface.
- Opening folders, files, and temporary previews must not push or reflow the whole screen.

The Knowledge folder hierarchy, themes, metadata fields, and file-preview template are not yet frozen and must remain undecided until the user defines them.

## Shared boundary

- No backend, AI automation, database, or persistent local-file bridge is part of the current V1.
- The public GitHub Pages project remains the interface shell and example prototype.
- Local file access and AI-assisted updates belong to a later private version.
